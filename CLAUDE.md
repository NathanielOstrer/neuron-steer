# neuron-steer

Exploration of single-neuron steering on Qwen3.5-4B. The README has the recipe, the run commands and the findings.

## Conventions

- This repo is public. Do not commit personal data, hostnames, tailnet names, home paths or tokens. `*.err` logs stay out of git because they contain local paths. Before each push, run `gitleaks git .` and grep the diff for the hostnames and paths in `CLAUDE.local.md`.
- `steer.py` is the research harness: bf16 weights via transformers on MPS, so it matches the original model exactly. It needs about 9 GB of free RAM. When the mini is swapping, it stalls in Metal submit at about 4% CPU instead of failing.
- The chat runs on MLX instead: `uv run serve.py`, then open http://127.0.0.1:8120. `mlx_steer.py` applies the same recipe to `mlx-community/Qwen3.5-4B-8bit` (about 4.5 GB, about 20 tok/s). Its outputs match bf16 almost word for word. One worker thread owns the model, because MLX streams are per thread. The server runs on demand, not under launchd, so it does not hold RAM all the time.
- This machine's hosting setup (agent, hostname, secrets path) is in `CLAUDE.local.md`, which is gitignored. Keep it out of this file.
- `sandbox.sb` and `run-sandboxed.sh` confine the hosted server: it can read only the repo, the interpreter, the HF cache and its secrets dir. It cannot write files, start programs, fork or connect out. The launcher must exec `.venv/bin/python`, not the resolved interpreter, or the venv is skipped. The sandbox cannot restrict the listen address.
- MLX traps: `Module.state` is a reserved property, and the outer `Model.layers` is a read-only property. Use `text_model()` to reach the real layer list. Qwen3.5 decoder layers need an `is_linear` attribute on any wrapper.
- Load the model on CPU, then call `.to("mps")`. `device_map="mps"` segfaults (exit 139) during weight load on this setup.
- The linear-attention layers run on the slow PyTorch fallback because `flash-linear-attention` and `causal_conv1d` are CUDA-only. Each prompt takes about 10-20 s for 150 tokens.
- Save run outputs under `runs/`. Political runs go in `runs/politics/` as JSON.
- Political eval: `evals/politics.jsonl` has 40 topics (20 econ, 20 social), each with 3 left-coded and 3 right-coded statements. Related topics share a split. Rank candidates on `train` only. Report results on `test`. `politics.py` holds the scoring math and has no model code. `eval_politics.py` scores on MLX from the first answer token: P("Ag") vs P("Dis"), averaged over both option orders.
- Read lean together with `decisiveness` and `acquiescence`. A steer that breaks comprehension drives lean to 0 by driving decisiveness to 0. A steer that agrees or disagrees with everything drives lean to 0 through acquiescence. Neither is a political shift.
- `find_neurons.py` ranks neurons three ways (persona direction, persona activation, gradient attribution). It then screens candidates by steering. Useful doses are 0.1 to 0.3. At dose 1, almost every candidate breaks the model.
- MLX gradients through Qwen3.5 need `model.train()`. The fused linear-attention kernel has no backward pass, and training mode switches to the plain-ops path. Also set `mx.set_cache_limit` and call `mx.clear_cache()` per pass. If you skip that, freed buffers push the mini into swap, and each pass slows from 2 s to 50 s.
- If argparse values start with a minus sign, pass them as `--doses=-0.3,0.3`. The `--doses -0.3` form fails.
- SAEs: `sae/train.py` trains TopK SAEs on CUDA. One forward pass feeds the SAEs for all layers. Run it on a rented GPU (see `CLAUDE.local.md`). Copy the weights back into `sae_out/`, which is gitignored at about 840 MB per layer. `sae_steer.py` ranks, shows and steers features on MLX. A feature dose uses the same units as a neuron dose. `sae_generate.py` prints greedy answers with one feature at several doses and saves them to `runs/politics/gen-<name>.json`.
- `explain_neurons.py` describes neurons three ways: top and bottom contexts over `sae_out/tokens.npy`, a logit lens of `W_down[:, n]`, and the nearest SAE features by decoder cosine. It stops the forward pass after the deepest requested layer. It scans about 720 tok/s on the mini, so 1000 sequences take about 12 minutes. Output goes to `runs/neurons/`.
- Mixing: `personas.json` is the catalog. `neurons` holds the published zoo neurons plus our own, with a `verdict` from re-running them on 8-bit. `features` holds concept features, and `recipes` holds named mixes. `mix.py catalog --list <key> --name <run>` runs a list on four fixed prompts (greedy, repetition penalty 1.05, the zoo's setting). `mix.py spec "15:4041:0.6,f9:19463:0.6" --name x` runs one spec. A spec mixes neurons (`L:N:dose`) and SAE features (`fL:F:dose`). Output goes to `runs/mix/<run>.json`. A rerun skips entries whose name and spec are already saved, so a crashed run resumes.
- Chat presets: the chat offers every entry of `personas.json` whose verdict held up (`mix.chat_presets`; `CHATTABLE` lists the verdicts), with the `chat` list first (the evil recipe, Golden Gate, the political dials). A new catalog entry with a good verdict appears in the chat after a server restart. If it uses an SAE feature, run `.venv/bin/python mix.py rows` first: the sandboxed server reads feature rows only from `chat_rows.safetensors` (about 30 KB), never from `sae_out/`. The worker keeps one preset applied and switches only for a steered request, because dose 0 is the plain model under any preset. After a change, restart the hosted server (the command is in `CLAUDE.local.md`).
- Two neurons in one layer stack as nested `SteeredDown` wrappers. `Steering` unwraps before it reads `W_down`.
- `census/census.py` is the steering census for a CUDA GPU: every neuron, both signs, one prompt ("Who are you?"), greedy, with a coherence score (NLL under the plain model) per reply. `bench` measures throughput. `run` writes one JSONL per layer and sign and resumes from what is there. It needs `sae/setup.sh` on the instance. `causal-conv1d` does not build there (no `nvcc`), and that costs little. Pilot on an A100 (2026-10-27): 22 ms per reply at batch 256, so the full census of 589,824 replies is about 3.6 h. A full-vocabulary `cross_entropy` on transposed logits once made it 5x slower, so keep `reply_nll`. `census.py retry --dose 0.5` re-runs the replies that `label.triage` calls broken. `census/label.py` labels the rest on the same GPU with the plain model: rules for broken and assistant replies, a JSON label (persona, category, weirdness) for the others. At dose 1, layers 0 and 1 mostly give empty replies.
- Atlas pipeline, after the census shards are copied to `runs/census/` (gitignored): `census/atlas.py merge` keeps the strongest coherent dose per neuron (1, else the 0.5 retry), `census/label_claude.py --census runs/census/merged` labels the changed replies with Haiku through `claude -p` (6 calls at a time, 40 replies a call, uses the user's plan, resumable), and `census/atlas.py build` writes `atlas/data.json`. `atlas/data.json` is gitignored: it is 22 MB, and nobody has read its Haiku labels, some of which are dark (a Holocaust victim, a corpse). The chat serves it at `/atlas` (gzipped once per file change). Each card's Chat button opens `/?spec=L:N:dose&label=...`. The server accepts such a custom spec only for neurons (at most 6, |dose| <= 2), never features, because the sandbox has only the preset feature rows.
- To chain GPU jobs, wait on a PID (`while kill -0 $PID`) or a marker file. `while pgrep -f "census.py run"` matched its own command line and waited forever on 2026-10-28, leaving the A100 idle for 75 minutes. Then the retry failed at once because the instance still had the old `census.py` without `retry`. After any local change to `census/`, copy it to the instance again, and check that a queued job's first step really started (log line or output file), not just that its shell exists.
- With two Thunder instances, `tnr` indices shift. Run `tnr status --no-wait --json` and match the `uuid` before `tnr delete <index>`. `tnr scp` to a new instance saves its key in `~/.thunder/keys/<uuid>`.
- Multi-neuron search: `find_combo.py` (MLX: candidate pools, single screens, beam search scored on train with penalties for acquiescence, decisiveness and coverage) and `gpu_combo.py` (the same eval in bf16 on CUDA, for controls and dose curves). `combo.py` holds the pure helpers. Results and the write-up are in `runs/politics/combo-*.json` and `combo-report.md`. The best combos are chat presets.
- `find_concepts.py` finds SAE features by regex over their top-20 contexts. It needs no model and takes about 8 s for 25 concepts.
- Tests: `uv run --no-project --with pytest --with torch --with safetensors --with numpy --with mlx-lm==0.32.2 python -m pytest -q tests`. Add `--model` to also run the tests that load the 8-bit model (about 4.5 GB, 25 s).
- `docs/index.html` is the results page. After a new run, run `python3 build_viz.py`, which embeds `runs/` between the DATA markers. The page script must not contain the literal marker strings, or the build pastes the data into the script. A new run file or prompt needs a matching entry in `build_viz.py` (`PROMPTS`, `names`) and in `CONDS` in the page.

## Next steps

1. Mine the atlas for chat presets. Pick 20 to 30 strong finds (high weirdness, coherent), check each on the four `mix.py` prompts, and add the ones that hold up to `personas.json` with a verdict. The census used one prompt only, and the Qwen3-8B census found that a third of strong replies change when the batch changes.
2. Run the political eval on two or three other open models. Everything so far is Qwen3.5-4B, so nobody knows if the controls or the lean carry over. This is the first thing a reader of the public repo will ask.
3. If the user wants the atlas public, read the dark labels in `atlas/data.json` first (a Holocaust victim, a corpse), then decide between committing it (22 MB) and publishing it somewhere else. It is gitignored since 2026-11-08.
4. Weight the social axis in the combo search. Free Market Four moves economic lean twice as far as social (−0.31 vs −0.16). Rerun `find_combo.py` with a score that requires both, and screen from the L8 neurons that carried the social shift.
5. Score mixes with a judge instead of by eye. The `verdict` fields in `personas.json` are one reader's labels from 4 prompts. An LLM judge on 20+ prompts would turn "13 of 18 fused" into a measured rate, and would show which neuron wins in the `one-wins` mixes.
6. Map a mix's dose budget. Sweep a fused pair (`holy-cookie`, `evil-poet`) over a grid of the two doses and record where it fuses, where one wins, and where it breaks. The full-dose flatterer + contempt pair broke, and 0.7 + 0.7 did not.
7. Find persona features by behavior, not by keyword. `find_concepts.py` picks features that fire on a word, and those mostly break the model when steered. Rank features by gradient attribution against a persona prompt, as `find_neurons.py attrib` does for neurons.
8. Map the libertarian feature L9 F7620 further. Sweep doses 0.4 to 0.6 in finer steps on the test split. Check whether nearby features (cosine with its decoder row) push right with higher decisiveness. Dose 0.5 gives lean −0.36 on test with acquiescence at baseline, but decisiveness drops from 0.51 to 0.44.
9. Measure the free-text effect. `sae_generate.py` answers at dose 0.5 shift framing (freedom, government as the cause) but stay both-sides. An LLM judge scoring left/right on 20+ open questions would quantify it. Try doses 0.6 to 0.8 there too, where coverage is still 0.95.
10. Look for a social-conservative feature. F7620 is libertarian. The conservative-media (F18862) and Christian-faith (F12905) features lower lean mostly by lowering decisiveness. Screen more features from the L16 and L23 rankings (`runs/politics/sae-candidates.json`), which were not screened.
11. Run `steer.py --baseline` once to check the switch to the text-only `Qwen3_5ForCausalLM` class (2026-10-26). It was untested because the mini was too short on memory.
12. Run L14 N8949 alone at dose 0.5 to find out if the two evil neurons are synergistic or if L13 just adds coherence.
13. Steer L11 N8529 and check if it is a usable dial. Its logit lens promotes freedom/liberty/relief tokens and suppresses tighten/consolidate/closure. It is also a persona-direction candidate (`runs/neurons/explain.out`).
14. Find out why L13 N7956 is in the evil recipe. It fires on rule exceptions and overrides, and the recipe steers it negative, which does not obviously read as evil.
